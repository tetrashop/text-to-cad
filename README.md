## 📝 Abstract (چکیده علمی)
The "Semantic Gap" between human intent (text/images) and precise parametric CAD modeling is a major bottleneck in modern engineering. **Text-to-CAD & Vision-to-CAD** is a fully deployed, cloud-native application that leverages Multimodal Large Language Models (MLLMs) to bridge this gap. The system is built on a robust microservices architecture: a frontend hosted on Vercel for user interaction and 3D rendering (Three.js), and a Python/FastAPI backend hosted on Render (via Docker) for heavy geometric computation. The backend utilizes a headless OpenSCAD engine to execute Constructive Solid Geometry (CSG) operations generated by Vision-Language Models (like Qwen-VL). This document outlines the system architecture, empirical testing, iterative engineering methodologies (including failure analysis and mitigation strategies), and the future roadmap for a production-grade application.

---

## 🏗️ 1. System Architecture (معماری سیستم)
To ensure scalability and prevent serverless limitations, the system is decoupled into a modern cloud-native architecture:

*   **Frontend (Vercel):** Handles UI/UX, client-side image compression (Canvas API) to reduce payload size, and 3D rendering via `Three.js`.
*   **Backend API (Render):** A FastAPI server running inside a custom Docker container.
*   **CAD Engine (Docker Container):** Executes headless OpenSCAD. Includes `xvfb` (X Virtual Framebuffer) to allow OpenSCAD to run without a physical GPU/Display.
*   **AI Core (OpenRouter):** Utilizes open-source Vision-Language Models (e.g., Qwen-VL, Llama 3) to parse the input and generate raw code.
*   **Network Mitigations:** Includes custom CORS configurations (`allow_credentials=False`) and a "Cold Start Ping" mechanism to wake up the free-tier Render server before sending heavy POST requests.

## 🔬 2. Engineering Methodology & Iterations (تکامل و تحلیل خطاها)

### Phase 1: The OpenSCAD Serverless Failure
Initial attempts used a Vercel-only architecture. **Failure Analysis:** Vercel Serverless functions timed out during complex Boolean operations. Raw LLMs demonstrated severe "Spatial Reasoning Deficits" (e.g., failing to place a cone on a cylinder).

### Phase 2: Dockerization & Headless Rendering
**Solution:** A `Dockerfile` was created (based on `python:3.11-slim`) installing `openscad` and `xvfb`. A wrapper script (`openscad-headless`) was implemented. The FastAPI backend was deployed on Render to bypass execution limits.

### Phase 3: Dual-Engine Attempt (CadQuery) & OOM Failure
**Attempt:** To achieve industrial precision (B-Rep modeling, Fillet), the backend was migrated to a Dual-Engine (CadQuery with OpenSCAD fallback). 
**Failure Analysis:** The free tier of Render (512MB RAM) was insufficient to load the heavy `CadQuery` (OpenCASCADE) C++ library, causing Out-Of-Memory (OOM) crashes.
**Resolution:** The system was reverted to the highly stable, lightweight OpenSCAD engine to ensure reliability on free-tier hosting.

### Phase 4: Multimodal Integration (Vision-to-CAD)
**Solution:** The backend was upgraded to accept Base64 images. Prompt engineering was introduced to differentiate between:
*   **Mechanical Mode:** Focuses on exact coordinates, Boolean subtractions, and CSG.
*   **Architectural Mode:** Focuses on `linear_extrude` for walls, leaving room interiors empty, and subtracting doorways using `difference()`.

## 🧪 3. Empirical Testing & Success Cases (نتایج تست‌ها)

### Case Study 1: Mechanical Flange (Success)
*   **Prompt:** *"Create a 100x100 plate, 10mm thick, with a 20mm radius central hole and four 5mm radius holes at (40,40), (-40,40), etc."*
*   **Result:** Successful. The AI accurately generated OpenSCAD code. The model rendered precisely.

### Case Study 2: Architectural Floor Plan (Partial Success)
*   **Prompt:** *"Ignore furniture. Create a floor, raise external walls by 30, leave rooms empty, subtract doors."*
*   **Result:** The AI successfully mapped the geometry to an extruded 3D layout rather than a solid block. However, highly complex floor plans (with dense furniture) still confuse the free-tier Vision models.

## 💻 4. UI/UX Features (امکانات رابط کاربری)
The frontend has evolved into a professional CAD viewer:
*   **Image Preprocessing:** Client-side downscaling (600px max) and JPEG compression (0.6) to prevent network timeouts.
*   **Grid & Wireframe Toggles:** Allows engineers to inspect internal geometry.
*   **STL Export:** Direct download of the generated 3D mesh.
*   **Snapshot Tool:** Captures a PNG of the Three.js canvas.

## 🛠️ 6. Local Setup (راه‌اندازی محلی)
```bash
# Clone the repository
git clone https://github.com/tetrashop/text-to-cad.git
cd text-to-cad

# Setup backend
cd backend
pip install -r requirements.txt
export OPENROUTER_API_KEY="your_api_key_here"
uvicorn main:app --host 0.0.0.0 --port 8000

# Serve frontend (in a new terminal)
cd frontend
python -m http.server 8080
```
